# 이슈 생성

## 사용 시점

사용자가 이슈 초안이나 GitHub 생성을 요청했을 때 사용한다.

## 작성 규칙

- 요청의 종류에 맞는 양식을 `.github/ISSUE_TEMPLATE/`에서 확인하고, 적합한 문서가 없으면 `.github/ISSUE_TEMPLATE/issue.md`를 사용한다.
  - 버그 신고은(는) `.github/ISSUE_TEMPLATE/bug-report.md`에서 읽는다.
- 양식은 초안의 출발점이다. 요청에 맞게 항목을 추가·삭제하고, 관련 없는 빈 섹션은 생략한다.
- 실제로 제공된 스크린샷이 있을 때만 스크린샷 제목과 첨부를 넣는다. `groove:optional screenshot` 주석은 이 조건을 표시한다.
- 적합한 타입을 찾으면 제목 앞에 `[Type]`을 붙인다.
- `.github/groove-labels.json`의 라벨 이름과 용도를 분류 기준으로 읽는다.
- 대상 GitHub 저장소에 있는 라벨을 확인하고 목적과 영역에 맞는 라벨을 자동으로 선택한다. 한 이슈에 라벨을 여러 개 적용할 수 있다. 라벨을 찾지 못하면 초안에 표시한다.
- 확인한 사실만 작성하며 아직 실행하지 않은 검증이나 재현 결과는 그 상태대로 표시한다.

## 작업 절차

1. 대상 저장소를 확인하고 보고된 오류나 제안의 목적을 파악한다.
2. 버그는 실제 동작·재현 방법·기대 동작을, 기능은 제안 목적과 완료 기준을 채운다.
3. 제목, 본문, 적용할 라벨과 대상 저장소를 확인한다.

## 게시와 결과

사용자가 GitHub 생성을 요청했다면 이슈를 만들고 선택한 라벨을 적용한다. URL, 적용된 라벨, 실패한 작업을 보고한다.
