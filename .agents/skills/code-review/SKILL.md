# 코드 리뷰

## 검토

1. 요청된 범위와 기대 동작을 확인합니다. 변경을 리뷰할 때는 diff와 영향받는 호출부·테스트를 함께 봅니다.
2. 정상 경로 외에도 오류, 기존 데이터, 재시도에서 동작이 달라지는지 확인합니다. 판단에 필요한 검증이 있다면 프로젝트의 기존 명령을 사용합니다.
3. 구체적인 영향을 확인할 수 있는 문제에 집중하고, 별도 수정 요청이 없으면 검토 결과를 보고하는 데 그칩니다.

## 결과

중요도 순으로 문제, 재현 조건, 영향과 파일 위치를 적습니다. 발견한 문제가 없다면 그 사실을 밝히고 검증하지 못한 범위를 적습니다.
